# Student Collector V2：G1 动态采集模板引擎计划

## 1. 模板生命周期

```text
草稿 -> 校验通过 -> 发布 -> 锁定使用 -> 停用
                  \-> 新版本草稿
```

- `TemplateDefinition` 是模板身份；`TemplateVersion` 是不可变业务契约。
- 草稿可以编辑；发布前必须通过 Schema、Excel、导入和导出样例验证。
- 发布后的 `schema_json`、列映射、匹配规则、导出规则和 SHA256 一律不可更新。
- 采集会话、记录、资产和审核动作都保存 `template_version_id`。
- 修改模板只能复制为新版本；历史数据继续引用旧版本。

## 2. 字段 Schema

示例（只展示契约形状，不作为运行时 Python 配置执行）：

```json
{
  "key": "student-profile",
  "version": 1,
  "fields": [
    {"key": "name", "label": "姓名", "type": "text", "required": true, "unique": false, "order": 10},
    {"key": "gender", "label": "性别", "type": "choice", "choices": ["男", "女"], "order": 20},
    {"key": "study_type", "label": "就读类型", "type": "choice", "required": true, "choices": ["走读", "半走读", "住宿"], "order": 30},
    {"key": "photo_key", "label": "照片匹配名", "type": "image_key", "required": false, "matching": {"enabled": true}, "order": 40}
  ]
}
```

允许类型及校验：

| 类型 | 存储 | 校验 |
| --- | --- | --- |
| `text` | Unicode 字符串 | 长度、正则、空白归一化 |
| `integer` / `decimal` | 规范化字符串 + 类型值 | 范围、千分位、禁止公式 |
| `date` | ISO 日期字符串 | 明确时区和格式 |
| `choice` | 选项稳定值 | 只接受已发布选项 |
| `boolean` | `true/false` | 明确空值语义 |
| `image_key` | 匹配键字符串 | 仅作为匹配输入，不直接形成文件路径 |
| `attachment` | `CollectionAsset` 关联 | 扩展名、MIME、大小、SHA256 |

唯一性分为三类：项目全局唯一、模板版本内唯一、项目+采集范围内唯一。动态唯一值写入 `RecordUniqueValue`，数据库唯一索引和服务端校验双重保证。

## 3. Excel 契约

每个模板下载包包含：

1. 主工作表：按 `order` 输出列，第一行是填写说明，第二行是示例/枚举说明，第三行开始数据。
2. `字段说明`：字段标识、显示名称、类型、必填、唯一、选项、示例和填写规则。
3. `模板元数据`：项目 slug、模板 key、版本号、Schema SHA256、生成时间。

导入优先使用 `模板元数据` 的稳定字段 key；没有元数据时按旧版显示名称映射。列映射允许管理员在模板版本草稿中调整，但发布后锁定。

导入流程：

1. 文件扩展名、实际 ZIP/OLE 结构、大小和上传配额检查。
2. 读取元数据并选择模板版本；版本不存在或 SHA256 不一致时阻断。
3. 逐行、逐字段类型校验，保留行号、列名、原始值和错误码。
4. 规范化唯一键并检查同文件重复、已有项目重复和同范围重复。
5. 生成只读导入预览；只有管理员确认或公开提交最终确认后才创建记录。
6. 失败预览不写正式记录、不写照片绑定、不覆盖旧版本。

V1 内置预设：

- 字段：姓名、性别、学部、学年、年级、班级、就读类型、备注。
- `学生编号`、`照片文件名` 保持旧数据读取兼容，但不再作为当前默认模板必填列。
- 2024/2025/2026 的旧版无年级名单继续使用旧映射；新版模板中的年级字段按当前在读年级解释。
- 就读类型唯一契约为：走读、半走读、住宿；历史“非走读”只在兼容读取层归一化为“住宿”，不得在新模板中重新生成“非走读”。

## 4. 照片和附件匹配

模板版本可声明匹配键顺序，例如：

```text
显式 image_key -> 稳定唯一字段 -> 唯一姓名 -> 人工确认
```

规则：

- 同名、同键多学生永不随机绑定；标记为人工确认。
- 同一采集批次一个学生只能有一个有效主照片；重复绑定在数据库和服务端最终审核时再次检查。
- 原始文件名、存储名、SHA256 和匹配动作分别保存，命名模板只作用于导出。
- 未匹配照片保留为异常资产，不能通过“导入预览成功”绕过最终校验。

## 5. 导出规则

`export_json` 保存：目录层级、字段输出、附件类型、命名模板、重名策略和统计工作表配置。

- 导出读取采集时锁定的模板/配置版本。
- 动态字段进入 `学生明细`；不存在的字段输出空值并记录版本信息。
- 统计工作表中的人数、附件数量、缺失数使用数值单元格。
- 每个班级/范围目录都带对应 Excel；异常记录包含缺失源文件、校验失败、重复绑定、命名冲突和版本信息。
- 所有源文件先完整读取并校验 SHA256，再写入受控临时 ZIP；ZIP 写入失败整包删除。

## 6. G1 测试门禁

- 草稿编辑、发布锁定、复制新版本、历史版本读取。
- 7 种字段类型、必填/唯一/枚举/正则/数值边界。
- 旧版学生模板导入和 V1 导出不变。
- Excel 元数据缺失、篡改、错误列、公式注入、超长值。
- 同名学生、同一照片重复绑定、失败重试、断线恢复。
- 动态字段导出、跨模板历史数据隔离、ZIP CRC/SHA256 对账。
