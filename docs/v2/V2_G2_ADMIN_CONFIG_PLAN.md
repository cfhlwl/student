# Student Collector V2：G2 后台配置中心计划

## 1. 页面与职责

| 页面 | 作用 | 写入对象 | 权限 |
| --- | --- | --- | --- |
| 项目管理 | 新建、停用、复制项目；设置公开状态 | `CollectionProject` | owner |
| 模板设计 | 字段、选项、列顺序、唯一性、匹配和导出规则 | `TemplateVersion` 草稿 | owner/editor |
| 模板发布 | 运行校验、查看差异、发布不可变版本 | `TemplateVersion` | owner |
| 文件设置 | 扩展名、MIME、大小、数量、配额、保留期 | `ProjectConfigVersion` | owner |
| 审核流程 | 自动采用条件、人工审核、补传规则 | `ProjectConfigVersion` | owner/editor |
| 导出规则 | 目录层级、命名字段、统计列、异常工作表 | `ProjectConfigVersion` | owner/editor/exporter |
| 品牌设置 | 名称、说明、颜色、Logo、用途告知 | `ProjectConfigVersion` | owner |
| 成员权限 | 项目成员和角色 | `ProjectMember` | owner |
| 备份恢复 | 在线备份、验证、隔离恢复、清理 | 备份文件和审计 | owner |
| 审计日志 | 配置差异、审核、导出、备份、恢复、清空 | `AuditLog`/`ReviewAction` | owner/viewer（只读） |

保持 V1 UI 风格：桌面端使用左侧导航和卡片，手机端使用分组折叠；危险操作固定使用独立红色区域，不能与普通保存按钮相邻。

## 2. 配置版本与回滚

业务设置不直接覆盖当前值，而是：

1. 读取当前配置版本生成草稿。
2. 服务端校验 Schema、跨字段关系、配额和文件安全规则。
3. 显示差异、影响范围和生效时间。
4. 发布生成不可变 `ProjectConfigVersion`，更新项目的当前指针。
5. 新采集会话锁定当前配置版本；已有会话继续使用旧版本。
6. 回滚只把当前指针指向已经验证过的旧版本，并写审计日志；不修改历史采集数据。

不允许管理员在浏览页面时隐式创建默认配置。只读请求不得写数据库或生成媒体文件。

## 3. 权限模型

- 系统管理员：维护所有项目、安装、备份恢复和账户。
- 项目 owner：项目配置、成员、发布、清空本项目资料。
- editor：编辑模板草稿和业务设置，不能发布或清空。
- reviewer：审核提交、人工匹配、补传。
- exporter：筛选和导出，不能修改业务配置。
- viewer：只读统计和异常。

V1 `/admin/` 继续由 `is_staff` 保护，先映射为内置学生项目的系统管理员/owner；不能因新增项目权限而放开旧管理入口。每个写入口统一经过维护锁、CSRF、权限检查、表单校验和审计。

## 4. 配置校验重点

- 项目 slug、模板 key、字段 key、文件扩展名和目录名均使用白名单。
- 文件路径只能由服务端按项目/运行/记录 ID 生成，配置不能包含绝对路径或 `..`。
- 导出命名只允许字段 token，不允许模板执行代码；非法字符替换、同名后缀和 Excel 实际文件名必须可追溯。
- 配额必须同时小于部署层的 Nginx/Django/磁盘安全上限；显示实际有效值。
- 删除/停用项目默认软删除；涉及媒体的清理必须先备份、验签、维护锁和二次密码确认。
- 公开采集关闭后，页面和实际写入门禁必须一致；重新开启写入一条审计记录。

## 5. 审计与回滚记录

每次写操作至少记录：项目、配置版本前后 ID、操作者、时间、客户端 IP（按可信代理规则）、动作、目标、结果、错误码和影响数量。密码、上传凭证、原始文件内容不写入日志。

配置差异以 JSON Patch 风格保存，但只允许展示安全字段；敏感值只显示“已设置/未设置”。备份恢复记录备份 SHA256、数据库/媒体清单和恢复结果。

## 6. G2 测试门禁

- owner/editor/reviewer/exporter/viewer 的越权访问和跨项目隔离。
- 草稿、发布、回滚、并发发布和旧会话版本锁定。
- 只读 GET 无数据库写入。
- 维护期间模板、班级、命名、上传开关写入全部拒绝且不返回 500。
- 错误密码、错误二次确认、备份失败时零删除。
- 手机端配置表单、差异页、危险操作和下载按钮可用。
